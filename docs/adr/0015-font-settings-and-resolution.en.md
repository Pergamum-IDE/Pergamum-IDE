# ADR-0015: Font Selection and Font Resolution

- Status: Accepted
- Date: 2026-09-16

## Context

Pergamum allows users to select fonts in three places: App UI, Editor, and Preview. Font settings exist in both application settings and project settings. Project settings are saved in the same location as `.pergamum`, so they move with the project to another machine. Installed fonts vary by machine, and even for the same font, the family name may differ depending on the OS.

CSS automatically falls back when a font is missing without notifying the user. Glyph-level fallback rendering (such as when variant selectors are unsupported) does not modify the source text, but displays as a different character on screen.

Font enumeration relies on Chromium's `window.queryLocalFonts()`. This API can only be invoked when triggered by a user action.

Pergamum does not exclude users who use non-Japanese writing systems (such as Hangul, Simplified Chinese, Traditional Chinese, etc.).

## Decision

### Slots and Setting Values

- **F-1** The font slots shall be three: "App UI", "Editor", and "Preview".
- **F-2** The value of each slot shall be an ordered list whose elements are family-level fonts. Selection by weight/style unit (face) shall not be provided.
- **F-3** Each element of the list shall be stored as a pair of the family name passed to CSS and the display name in the UI language at the time of selection. It shall not be stored as a comma-separated string.
- **F-4** All elements in the list shall be required. The list expresses combinations such as Latin/Japanese fonts, and is not a list of fallback candidates.
- **F-5** Font settings shall take application settings as default values and be overwritten by project settings.
- **F-6** The CSS `font-family` property shall be generated by ordering the list elements sequentially and appending a generic family defined for each slot at the end. The generic family shall not be included in user setting values.
- **F-7** The Editor shall not use bold or italic styles.
- **F-8** `font-synthesis` shall use default values in all slots.
- **F-9** The `lang` attribute for all slots shall be set to the UI language specified in application settings.

### Font Cache

- **F-10** `queryLocalFonts()` shall only be invoked when triggered by a user action.
- **F-11** Enumeration results shall be saved under `userData` as a family-level font cache. The font cache is machine-specific information and shall not be included in the project.
- **F-12** The font cache shall store, for each family, the family name passed to CSS, the display name, and the fixed-width attribute (F-23).
- **F-13** Pergamum shall not perform character-set coverage checks per writing system (e.g. whether it contains Latin characters, Japanese characters, etc.).
- **F-14** For the family name passed to CSS, `FontData.family` returned by `queryLocalFonts()` shall be used directly.
- **F-15** Display names shall be retrieved from the `name` table of font files. Targeting all faces belonging to the same family, the first value obtained in the following order shall be used:
  1. `nameID` 16 in the UI language
  2. `nameID` 1 in the UI language of the face whose `family` matches `nameID` 1 in English
  3. `family`
- **F-16** Display names and family names shall be preserved as recorded in the font without normalization. Matching shall be performed by exact match.
- **F-17** `FontData.fullName` shall not be used.
- **F-18** Families lacking Regular (weight 400 non-italic face) shall not be excluded from the list.

### Matching and Notification

- **F-19** At application startup and when opening a project, each element of the effective font settings shall be matched against the font cache. Matching shall be performed in the order of the family name passed to CSS, followed by the display name, and the family name of the matching cache item shall be passed to CSS.
- **F-20** The matching result shall be categorized into three states:
  - **Not scanned**: The font cache does not exist. Inform the user that font information has not been acquired, and do not issue a missing font warning.
  - **Missing in cache**: One or more elements do not exist in the cache. Display a notification toast naming the missing elements, including a rescan action in the toast.
  - **Still missing after rescan**: One or more elements still do not exist after rescanning. Confirm the absence and indicate on the UI that fallback rendering is active.
- **F-21** Regardless of the matching result, Pergamum shall not modify the font setting values.
- **F-22** Glyph-level fallback rendering shall be out of scope for detection. Display "Depending on the font, variant selectors or specific glyphs may not display correctly" in the font selection dialog.

### Fixed-Width Detection

- **F-23** A fixed-width font is defined as a font that satisfies both of the following conditions:
  - The advance width of `W` and `i` are equal.
  - The advance width of two `W` characters is equal to the advance width of one `Ｗ` (U+FF37) character.
- **F-24** Detection shall be performed by actual measurement using Canvas `measureText`. For each measurement character, confirm that the width matches under two specifications with different generic families to guarantee measurement with the target font's own glyphs.
- **F-25** For a multi-element list, perform the F-23 determination with the entire list specified, and display the result in the dialog.
- **F-26** The font selection dialog shall have a "Fixed-width fonts only" switch. The default value of the switch shall be OFF. The Editor slot shall not be restricted to fixed-width fonts.

### Font Selection Dialog Sample Field

- **F-27** The dialog shall have an editable sample field for the user. Its initial value shall be defined in i18n resources for each UI language.
- **F-28** Edits to the sample field shall not be saved.
- **F-29** The font list and sample field in the dialog shall be rendered with `font-weight: 400`, matching the body text of each slot. The actual appearance of families lacking Regular shall be shown in this rendering before selection.

## Consequences

- When opening a project on a different machine, missing fonts are notified to the user while setting values are preserved. Returning to the original machine restores the original display.
- Even if the font cache is stale, the user can rescan in a single action from the notification toast.
- Because character-set coverage checks per writing system are not performed, detection of "unused elements" or warnings regarding element ordering are not provided. The validity of element ordering is verified by the user in the sample field.
- Because fixed-width detection measures only `Ｗ` as a full-width character, whether Hangul or other character widths match full-width is not guaranteed.
- Glyph-level fallback rendering is not notified.
- Because family aggregation is performed by Chromium, Pergamum does not bundle faces of different weights itself. A parser for the `name` table is maintained for retrieving display names.
- Families consisting of only a single weight (such as BIZ UD Mincho, HG Mincho B, etc.) can also be selected.
- Characters not included in the list's elements are rendered in a font selected by Chromium based on the `lang` attribute. If the UI language differs from the manuscript language, and fonts containing the manuscript's characters are not included in the list, glyphs may not match the manuscript's language.

## Out of Scope

- Weight selection UI
- Detection of glyph-level fallback rendering (including diagnostics via DevTools Protocol)
- Character-set coverage checks per writing system
- Persistence of sample field content
- Manuscript language setting independent of UI language
